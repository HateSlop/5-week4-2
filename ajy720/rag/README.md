# 소니 미러리스 카메라 RAG FAQ 구현 결론

소니 일본 공식 사양표에서 미러리스 카메라 18종의 데이터를 수집하고, `text-embedding-3-small` 임베딩과 Chroma DB 검색을 이용해 한국어 FAQ를 만들었다. 일반적인 답변 생성에는 `gpt-4o-mini`를 사용했다. 수집·검색·생성 코드는 [노트북](rag.ipynb), 원문은 [source_data](source_data/), 직접 구성한 질문 10개와 생성 답변은 [FAQ](faq.md)에 정리했다.

## A. 공식 사양표 수집

제품 페이지의 링크에서 모델을 찾고 각 모델의 사양표와 주석을 추출했다. 소니코리아에 대한 자동 요청은 403 오류가 발생해 일본 공식 사이트를 사용했다. 수집한 일본어 원문에는 제품명, 모델 ID, 출처 URL과 수집 시각을 함께 저장했다.

수집된 모델은 풀프레임 14종과 APS-C 4종이다. **답변의 범위는 수집한 18종의 일본 사양으로 한정해야 한다.** 한국 판매 여부나 소니의 역대 전체 라인업을 설명하는 자료로 해석할 수는 없다.

## B. 청크 분할과 벡터 DB

사양표의 섹션을 유지하면서 긴 섹션은 1,200자 단위로 나누고 150자를 겹치게 했다. 각 청크에 모델명과 출처를 붙이고, 일본어 항목에 센서·화소·연사·무게 같은 한국어 검색어를 덧붙였다. 센서·유효 화소·마운트 항목을 원문에서 추출한 전체 모델 요약도 저장했다. Chroma DB에는 요약 문서를 포함해 총 648개 문서가 저장됐다.

**원문을 저장하는 것과 질문에 필요한 근거를 검색하는 것은 별개의 단계다.** 모델과 사양 항목을 식별할 수 있는 정보가 검색 문서에도 남아 있어야 답변의 근거를 확인할 수 있다. 다만 한국어 검색어 추가의 효과를 별도 실험으로 측정하지는 않았다.

## C. 모델별 검색과 FAQ 생성

모델이 명시된 질문은 해당 모델 안에서 유사도 상위 3개 청크를 검색했다. 두 모델을 비교하는 질문은 모델별로 검색해 한쪽 자료가 누락되지 않도록 했다. 생성 프롬프트에는 사진·영상 유효 화소, 본체만의 무게·배터리 포함 무게, 셔터 조건을 구분하고 문서 ID를 인용하도록 지시했다.

생성된 FAQ에는 α7 V의 최대 약 3300만 화소, α9 III의 Hi+ 전자 셔터 연사 최대 약 120장/초, α7C II의 배터리·메모리카드 포함 무게 약 514g 등의 답변이 포함됐다. 해당 수치와 조건은 수집 원문에서 확인했다. **사양의 숫자뿐 아니라 촬영 모드와 측정 조건도 함께 전달해야 한다.** 문서 인용이 있다는 이유만으로 답변 전체가 정확하다고 판단할 수는 없다.

## D. 전체 모델의 화소 비교 오류와 개선

초기에는 “제일 화소수가 높은 카메라가 뭐야?”라는 질문에 α7R IV의 6100만 화소를 답하면서 “수집한 문서에서 확인할 수 없습니다”라는 문장도 출력했다. 원문에 화소 데이터가 있었지만, 유사도 상위 3개 청크만으로는 전체 모델의 화소를 비교할 근거가 충분히 전달되지 않았다.

모델을 지정하지 않은 질문에는 원문에서 추출한 전체 모델 요약을 검색 결과에 반드시 포함하도록 수정했다. 사진 유효 화소의 최고·최저 질문은 DB 요약의 수치를 코드로 비교하고 동률 모델도 모두 답하도록 했다. 이는 LLM이 비교 결과를 생성하는 방식과 구분된다.

수정 후 CLI에서 전체 모델의 최고 화소 질문은 **α7R VI의 최대 약 6680만 화소(66.8MP)**, APS-C 모델의 최고 화소 질문은 **α6700과 ZV-E10 II의 최대 약 2600만 화소(26MP)**를 반환했다. **전체 집합의 순위를 묻는 질문은 일부 유사 문서의 검색만으로 해결하기 어렵고, 비교 대상 전체와 명확한 수치 비교가 필요하다.**

## E. 터미널에서 질문하기

[faq.py](faq.py)를 작성해 `python faq.py "제일 화소수가 높은 카메라가 뭐야?"`처럼 질문하면 답변과 인용된 공식 출처를 출력하도록 했다. CLI는 이미 생성된 Chroma DB를 재사용한다.

처음 실행할 때는 `OPENAI_API_KEY`를 환경변수 또는 레포 루트 `.env`에 설정하고, 필요한 패키지를 설치한 환경에서 `rag.ipynb`를 먼저 실행해야 한다. 생성된 DB와 API 키는 Git에 포함하지 않았다.

## 종합 결론

공식 사양표 수집, 임베딩, Chroma DB 검색, 한국어 답변 생성까지 연결해 소니 미러리스 카메라의 종류와 스펙을 질문할 수 있었다. 모델별 사양과 비교 질문에는 해당 모델의 근거를 검색했고, 전체 화소 순위 질문에는 전체 모델 요약과 수치 비교를 적용했다.

이번 구현에서 확인한 핵심은 **데이터가 원문에 존재한다고 해서 RAG가 자동으로 올바른 답을 내는 것은 아니라는 점**이다. 질문의 범위에 맞는 검색, 비교에 필요한 전체 데이터, 사양 조건의 보존을 함께 확인해야 한다.

## 검증의 한계

결과는 수집한 18종, FAQ 질문 10개와 추가 CLI 확인 사례에 대한 관찰이다. 별도의 정답 데이터셋이나 검색 정확도 측정, 반복 실험은 수행하지 않았으므로 모든 질문에 대한 정확성을 보장하지 않는다. 사진 유효 화소의 수치 비교는 현재 원문 형식과 특정 질문 표현에 맞춰 구현했으며, 영상 화소나 다른 사양의 전체 순위 비교에는 적용하지 않는다.

저장된 원문과 DB를 재사용하므로 이후 사양 변경이 자동으로 반영되지는 않는다. 최신 자료가 필요하면 노트북의 재수집·DB 재생성 플래그를 설정해 다시 실행해야 한다.
